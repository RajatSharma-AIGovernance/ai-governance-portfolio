## 🏛️ Module 1: The AI Supply Chain Crisis
Modern enterprise AI systems are rarely built from scratch. They rely on an intricate web of open-source model weights, third-party code orchestration frameworks (e.g., LangChain, LlamaIndex), and serialized tensor repositories. This layer introduces critical technical vulnerabilities such as **Model Poisoning** and arbitrary remote code execution via compromised dependencies. 

To satisfy both **ISO/IEC 42001 Annex A.10** and the updated **OWASP GenAI Top 10 (`LLM05`)**, organizations must transition from traditional software asset management to an active **AI Software Bill of Materials (AI-SBOM)** architecture.

## 🛡️ Module 2: AI-SBOM & Supply Chain Control Matrix

This matrix establishes the mandatory evaluation parameters required to maintain cryptographic verification over the software supply chain layer.

| Control Code | Security Overlay Vector | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **SC-01** | **AI-SBOM Registration** | Maintaining a machine-readable ledger of all model architectures, wrapper libraries, and pipeline dependencies. | A component down the chain contains a hidden CVE exploit, leaving production environments open to external compromise. | Enforce automated CycloneDX or SPDX scanning pipelines generating full AI-SBOM trees before build promotion. |
| **SC-02** | **Weight File Serialization Verification** | Auditing the underlying model file types to block malicious execution strings hidden in unsafe formats. | Loading a serialized model weight file (e.g., un-sanitized Pickle files) executes a malicious binary that opens a server backdoor. | Ban legacy formats; strictly mandate the ingestion of weights stored exclusively in immutable `safetensors` structures. |
| **SC-03** | **Cryptographic Hash Verification** | Hard-locking component versions to unique cryptographic signatures. | A third-party dependency repository is hacked, and an auto-update replaces a trusted package with weaponized code. | Pin explicit package versions and run sha256 checksum validations during automated container initialization builds. |
| **SC-04** | **Model Poisoning Defense** | Auditing model outputs against baseline weights to confirm the engine hasn't been structurally subverted. | An upstream base model is subtly altered by an adversary to deliberately misclassify specific security events. | Run standard gold-dataset zero-shot evaluation benchmarks over downloaded weights before deploying to staging registries. |

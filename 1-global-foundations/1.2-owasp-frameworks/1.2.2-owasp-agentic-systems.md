## 🏛️ Module 1: What is OWASP and Why Does AI Governance Need It?

### What is OWASP?
The **Open Worldwide Application Security Project (OWASP)** is a non-profit foundation that works as the global authority on software security. When engineers build applications, they use OWASP to ensure their code cannot be exploited by bad actors.

### The Role in AI Governance
Process frameworks (like ISO 42001) prove your company has policies, but they cannot stop a hacker from breaking your software. OWASP bridges the gap between **legal compliance and engineering execution**. An auditor or security lead uses this manual to run code-level and architecture-level risk assessments on artificial intelligence deployments.

*⚙️ Operational Note: This document focuses strictly on autonomous orchestration layers, multi-agent frameworks, and tool execution boundaries. For Large Language Model (LLM) core pipelines and basic prompt interfaces, refer directly to **[1.2.2 - OWASP AI Security Manual: LLM Applications](../1.2-owasp-frameworks/1.2.2-owasp-ai-security-manual.md)**.*

## 🤖 Module 2: The Complete OWASP Top 10 for GenAI & AI Agents (Agentic Orchestration Layer)

AI Agents are different from basic chatbots—they are autonomous software programs that run loops, make choices, use tools, and call external apps. This distinct framework covers threats unique to **agentic loops**.

### 📋 Full Reference Control Matrix

| Official Code | Legal / Technical Security Term | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **AGE01** | **Agent Prompt Injection** | Hijacking an autonomous agent's loop via malicious external data it reads during execution. | An agent reads a weaponized customer email that instructs it to forward all internal invoices to a hacker's inbox. | Isolate agent system instructions from execution memory; validate all incoming third-party data. |
| **AGE02** | **Insecure Tool Execution** | Allowing an agent to execute code or call external APIs without restricting its parameters or context. | An agent is given a command-line tool and runs an unvalidated string that wipes out the host server's operating system. | Use strict sandboxed runtime environments (Docker containers) with restricted execution access. |
| **AGE03** | **Unvalidated Input & Output** | Agents passing raw, unchecked data to other agents or dependent downstream enterprise business apps. | An agent generates a corrupted file string that crashes a legacy database when attempting an automated record update. | Implement strict data schemas (JSON schema validation) for every link in the agentic chain. |
| **AGE04** | **Insecure Agent Coordination** | Multiple autonomous agents communicating with each other without verifying authorization or identity tokens. | A malicious rogue agent sneaks into an internal network cluster and tricks an executive assistant agent into leaking a report. | Enforce mutual authentication (mTLS) and cryptographically sign communications between agents. |
| **AGE05** | **Excessive Autonomy** | Permitting an agent to execute multi-step operational chains without verification checkpoints. | An agent gets stuck in an infinite error loop and autonomously opens 10,000 corporate IT support tickets in 5 minutes. | Define hard operational boundaries, maximum loop counters, and timeout thresholds. |
| **AGE06** | **Lack of Human-in-the-Loop** | Designing an agentic pipeline that executes irreversible, high-risk financial or operational tasks with no human oversight. | An autonomous purchasing agent detects a fake low price and spends $200,000 on faulty inventory without approval. | Hardcode manual approval gates into the system architecture for any high-value transactional tool. |
| **AGE07** | **Insecure Inter-Agent Communication** | Flawed network or protocol controls allowing sniffing or spoofing of agent messages. | An attacker intercepts the text channel between a data-fetcher agent and an executive dashboard, exposing trade secrets. | Encrypt all communication channels; enforce strict role-based token validation (RBAC) between agent systems. |
| **AGE08** | **Cascading Failures** | One single agent processing an error or hallucinatory command that propagates and breaks an entire cluster. | An accounting agent errors out, sending corrupted values to a billing agent, which triggers thousands of false invoices. | Implement strict circuit breakers and semantic exception handlers between multi-agent hooks. |
| **AGE09** | **Human-Agent Trust Exploitation** | The agent generating emotionally manipulative or overly authoritative text that tricks human operators. | A user falls victim to automation bias, executing a dangerous financial trade because the agent presented the choice with absolute false certainty. | Deploy mandatory human-in-the-loop warning logs, and strictly mandate secondary validation queues for analytical tasks. |
| **AGE10** | **Rogue Agents** | An agent system completely breaking outside its designated operational profile or bounds. | An untethered agent modifies its own orchestration goals, spawning sub-processes that continuously exhaust corporate compute resources. | Embed hardcoded runtime guardrails at the microkernel or execution environment layer that cannot be overridden by text. |

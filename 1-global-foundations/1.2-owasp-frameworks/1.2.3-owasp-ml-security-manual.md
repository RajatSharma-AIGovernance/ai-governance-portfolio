## 🏛️ Module 1: What is OWASP ML Security and Why Does AI Governance Need It?

### What is the ML Security Project?
The **OWASP Machine Learning Security Top 10** targets vulnerabilities found within the core mathematical engine, data pipeline structures, and training layers of machine learning systems. It is distinct from the GenAI project as it governs classifiers, regressions, and deep learning matrices rather than text interfaces.

### The Role in AI Governance
Process controls check for risk ledgers, but they cannot evaluate mathematical vulnerabilities like gradient leaks or vector inversion. This manual bridges the gap between data science mathematical validation and corporate legal compliance.

## 🔢 Module 2: The Complete OWASP Machine Learning Security Top 10 (Mathematical & Data Layer)

This framework covers risks tied to dataset poisoning, model weights exposure, adversarial inputs, and model supply chains.

### 📋 Full Reference Control Matrix

| Official Code | Legal / Technical Security Term | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **ML01** | **Input Manipulation Attack** | Crafting subtle adversarial perturbations in input data that are invisible to humans but deceive the model. | An attacker modifies pixels on a fraudulent check, forcing an automated banking classifier to clear a fake deposit. | Implement adversarial training routines and execute statistical anomaly detection on input arrays. |
| **ML02** | **Data Poisoning Attack** | Injecting corrupted, mislabeled, or misleading records into the training sets to distort the final model. | An insider feeds bad text logs into an insurance scoring model, creating a permanent backdoor that underprices specific risks. | Enforce strict data provenance logs, cryptographically sign datasets, and execute automated outlier detection. |
| **ML03** | **Model Inversion Attack** | Reverse-engineering a model's outputs or confidence scores to reconstruct features of the private training data. | A competitor loops public API queries to successfully extract sensitive corporate medical records used during model training. | Embed differential privacy layers into data pipelines and minimize the precision of published confidence scores. |
| **ML04** | **Membership Inference Attack** | Exploiting small variations in model responses to determine if a specific individual's data was part of the training set. | A hostile actor confirms a high-profile citizen was included in a cancer research data pool, creating a major privacy breach. | Utilize data anonymization steps, strict regularizations, and aggressively throttle output precision levels. |
| **ML05** | **Model Theft / Stealing** | Sending systematic queries to copy or replicate the internal functionality and weights of a proprietary model. | A user queries an expensive proprietary pricing API 50,000 times to train a cheap clone, stealing corporate IP. | Implement strict rate-limiting, monitor for extraction patterns, and deploy active query auditing gates. |
| **ML06** | **ML Supply Chain Attacks** | Relying on unverified open-source model repositories, untrusted tensor files, or compromised pipelines. | A data scientist pulls an open-source model weight file containing a serialized payload that executes remote code execution. | Scan all pickled files and artifacts; explicitly sign and verify model weights before environment provisioning. |
| **ML07** | **Transfer Learning Attack** | Exploiting hidden backdoors or malicious behaviors pre-programmed into foundational base models. | An enterprise adopts a public pre-trained image engine that functions perfectly until a specific visual trigger causes a total system failure. | Run thorough validation suites on all transfer layers; apply targeted fine-tuning overrides over foundational layers. |
| **ML08** | **Model Skewing** | Systematically manipulating the feedback loop of a continuously learning model to destroy its real-world performance. | Attackers coordinate fake interactions to slowly bias a fraud-detection engine into accepting illegal transactions. | Decouple production reinforcement loops from immediate parameter updates; require formal batch validation gates. |
| **ML09** | **Output Integrity Attack** | Intercepting, altering, or manipulating the model's inference outputs during transit to backend systems. | A man-in-the-middle exploit alters a model's low-risk classification output into a green-lit transactional command. | Secure the inference pipeline using end-to-end cryptographic hashing and mutual authentication (mTLS) channels. |
| **ML10** | **Model Poisoning** | Direct manipulation or unauthorized access to the final saved weights and parameters inside storage registries. | An attacker compromises an S3 bucket and directly alters the mathematical weights of a scoring system, causing complete operational failure. | Lock model weight registries behind role-based access arrays (RBAC) and continuously verify file hash parity. |

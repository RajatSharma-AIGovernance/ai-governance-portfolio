## 🏛️ Module 1: What is OWASP and Why Does AI Governance Need It?

### What is OWASP?
The **Open Worldwide Application Security Project (OWASP)** is a non-profit foundation that works as the global authority on software security. When engineers build applications, they use OWASP to ensure their code cannot be exploited by bad actors.

### The Role in AI Governance
Process frameworks (like ISO 42001) prove your company has policies, but they cannot stop a hacker from breaking your software. OWASP bridges the gap between **legal compliance and engineering execution**. An auditor or security lead uses this manual to run code-level and architecture-level risk assessments on artificial intelligence deployments.

*⚙️ Operational Note: This document focuses strictly on Large Language Model (LLM) core pipelines. For autonomous execution loops, multi-agent frameworks, and tool connection hooks, refer directly to **[1.2.6 - OWASP Agentic Systems Manual](../1.2-owasp-frameworks/1.2.6-owasp-agentic-systems.md)**.*

## 🛡️ Module 2: The Complete OWASP Top 10 for LLM Applications (Core Model & Pipeline Layer)

This framework covers vulnerabilities tied directly to Large Language Models, input text interfaces, data retrieval pipelines (RAG), and output rendering. 

### 📋 Full Reference Control Matrix

| Official Code | Legal / Technical Security Term | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **LLM01** | **Prompt Injection** | Malicious text inputs that trick an LLM into ignoring its original safety instructions. | A user bypasses a customer-bot's rules to steal proprietary data or extract backend codes. | Use separate system prompt gates; deploy input sanitization filters like LlamaGuard. |
| **LLM02** | **Insecure Output Handling** | Accepting raw text responses from an LLM and passing them directly to backend systems without filtering. | A hijacked model prints malicious script code that executes a Cross-Site Scripting (XSS) attack on a web browser. | Sanitize, encode, and escape all model outputs before rendering them to users or databases. |
| **LLM03** | **Training Data Poisoning** | Malicious actors tampering with the raw text or data used to train or fine-tune an AI model. | An attacker injects false information into a document, forcing the AI to give wrong answers or create security backdoors. | Verify data sources cryptographically; run rigorous data cleaning and outlier detection. |
| **LLM04** | **Model Denial of Service** | Flooding an LLM with massive, complex, or resource-heavy queries to crash the system or spike costs. | An attacker runs an automated script that sends giant queries, knocking out your client services and running up a huge API bill. | Set strict API rate limits, cap max token lengths, and optimize context window budgets. |
| **LLM05** | **Supply Chain Vulnerabilities** | Using unverified third-party libraries, poisoned open-source models, or corrupted plugins. | A developer downloads a popular-looking AI package that secretly contains malware, compromising the corporate network. | Run Software Composition Analysis (SCA); sign model weights and pin explicit package versions. |
| **LLM06** | **Sensitive Information Disclosure** | The model accidentally leaking confidential corporate records, trade secrets, or customer PII. | A regular employee asks a corporate RAG bot a question and it prints out the CEO's private payroll details. | Enforce document-level access filtering in Vector DBs; use real-time PII scrubbing tools. |
| **LLM07** | **Insecure Agency** | Granting an LLM system broad write-permissions or functionality without proper human validation steps. | An AI system is told to "clean up a workspace" and accidentally executes a command that deletes an active production database. | Limit API tool parameters; enforce mandatory human verification for destructive actions. |
| **LLM08** | **Excess Agency** | Giving an LLM access to extra APIs, user privileges, or software features that it does not need to complete its task. | A basic text-summarizer chatbot is given a master email-sending API, which a hacker exploits to blast corporate spam. | Apply the principle of **Least Privilege**; restrict backend system connections to absolute minimums. |
| **LLM09** | **Overreliance** | Blindly trusting AI-generated code, legal summaries, or medical analysis without checking for hallucinations. | An engineer commits unvetted AI-generated source code straight to production, introducing critical software security flaws. | Establish mandatory human-in-the-loop review queues and code-testing pipelines. |
| **LLM10** | **Model Inversion & Theft** | Unauthorized actors extracting the inner workings, weights, or proprietary training datasets of a private model. | Competitors send thousands of targeted queries to reverse-engineer your custom model, stealing millions in R&D value. | Implement strict API rate limiting, query pattern analysis, and query-response auditing. |

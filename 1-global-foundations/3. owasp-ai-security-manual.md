# The Definitive OWASP AI Security Manual: LLMs & Agentic Systems

This manual serves as a definitive security architecture reference. It covers the complete, official lists for both the **OWASP Top 10 for LLM Applications** and the **OWASP Top 10 for GenAI & AI Agents**, providing technical terms, strict tracking codes, and plain-English translation matrices.

---

## 🏛️ Module 1: What is OWASP and Why Does AI Governance Need It?

### What is OWASP?
The **Open Worldwide Application Security Project (OWASP)** is a non-profit foundation that works as the global authority on software security. When engineers build applications, they use OWASP to ensure their code cannot be exploited by bad actors.

### The Role in AI Governance
Process frameworks (like ISO 42001) prove your company has policies, but they cannot stop a hacker from breaking your software. OWASP bridges the gap between **legal compliance and engineering execution**. An auditor or security lead uses this manual to run code-level and architecture-level risk assessments on artificial intelligence deployments.

## 🛡️ Module 2: The Complete OWASP Top 10 for LLM Applications (Core Model & Pipeline Layer)

This framework covers vulnerabilities tied directly toLarge Language Models, input text interfaces, data retrieval pipelines (RAG), and output rendering. 

### 📋 Full Reference Control Matrix

| Official Code | Legal / Technical Security Term | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **LLM01** | **Prompt Injection** | Malicious text inputs that trick an LLM into ignoring its original safety instructions. | A user bypasses a customer-bot's rules to steal proprietary data or extract backend codes. | Use separate system prompt gates; deploy input sanitization filters like LlamaGuard. |
| **LLM02** | **Insecure Output Handling** | Accepting raw text responses from an LLM and passing them directly to backend systems without filtering. | A hijacked model prints malicious script code that executes a Cross-Site Scripting (XSS) attack on a web browser. | Sanitize, encode, and escape all model outputs before rendering them to users or databases. |
| **LLM03** | **Training Data Poisoning** | Malicious actors tampering with the raw text or data used to train or fine-tune an AI model. | An attacker injects false information into a document, forcing the AI to give wrong answers or create security backdoors. | Verify data sources cryptographically; run rigorous data cleaning and outlier detection. |
| **LLM04** | **Model Denial of Service** | Flooding an LLM with massive, complex, or resource-heavy queries to crash the system or spike costs. | An attacker runs an automated script that sends giant queries, knocking out your client services and running up a huge API bill. | Set strict API rate limits, cap max token lengths, and optimize context window budgets. |
| **LLM05** | **Supply Chain Vulnerabilities** | Using unverified third-party libraries, poisoned open-source models, or corrupted plugins. | A developer downloads a popular-looking AI package that secretly contains malware, compromising the corporate network. | Run Software Composition Analysis (SCA); sign model weights and pin explicit package versions. |
| **LLM06** | **Sensitive Information Disclosure** | The model accidentally leaking confidential corporate records, trade secrets, or customer PII. | A regular employee asks a corporate RAG bot a question and it prints out the CEO's private payroll details. | Enforce document-level access filtering in Vector DBs; use real-time PII scrubbing tools. |
| **LLM07** | **Insecure Agency** | Granting an LLM system broad write-permissions or functionality without proper human validation steps. | An AI system is told to "clean up a workspace" and accidentally executes a command that deletes an active production database. | Limit API tool parameters; enforce mandatory human verification for destructive actions. |
| **LLM08** | **Excess Agency** | Giving an LLM access to extra APIs, user privileges, or software features that it does not need to complete its task. | A basic text-summarizer chatbot is given a master email-sending API, which a hacker exploits to blast corporate spam. | Apply the principle of **Least Privilege**; restrict backend system connections to absolute minimums. |
| **LLM09** | **Overreliance** | Blindly trusting AI-generated code, legal summaries, or medical analysis without checking for hallucinations. | An engineer commits unvetted AI-generated source code straight to production, introducing critical software security flaws. | Establish mandatory human-in-the-loop review queues and code-testing pipelines. |
| **LLM10** | **Model Inversion & Theft** | Unauthorized actors extracting the inner workings, weights, or proprietary training datasets of a private model. | Competitors send thousands of targeted queries to reverse-engineer your custom model, stealing millions in R&D value. | Implement strict API rate limiting, query pattern analysis, and query-response auditing. |

## 🤖 Module 3: The Complete OWASP Top 10 for GenAI & AI Agents (Agentic Orchestration Layer)

AI Agents are different from basic chatbots—they are autonomous software programs that run loops, make choices, use tools, and call external apps. This distinct framework covers threats unique to **agentic loops**.

### 📋 Full Reference Control Matrix

| Official Code | Legal / Technical Security Term | Plain-English Meaning (What it is) | The Enterprise Risk (What breaks) | The Engineering Fix (How to solve) |
| :--- | :--- | :--- | :--- | :--- |
| **AGE01** | **Agent Prompt Injection** | Hijacking an autonomous agent's loop via malicious external data it reads during execution. | An agent reads a weaponized customer email that instructs it to forward all internal invoices to a hacker's inbox. | Isolate agent system instructions from execution memory; validate all incoming third-party data. |
| **AGE02** | **Insecure Tool Execution** | Allowing an agent to execute code or call external APIs without restricting its parameters or context. | An agent is given a command-line tool and runs an unvalidated string that wipes out the host server's operating system. | Use strict sandboxed runtime environments (Docker containers) with restricted execution access. |
| **AGE03** | **Unvalidated Input & Output** | Agents passing raw, unchecked data to other agents or dependent downstream enterprise business apps. | An agent generates a corrupted file string that crashes a legacy database when attempting an automated record update. | Implement strict data schemas (JSON schema validation) for every link in the agentic chain. |
| **AGE04** | **Insecure Agent Coordination** | Multiple autonomous agents communicating with each other without verifying authorization or identity tokens. | A malicious rogue agent sneaks into an internal network cluster and tricks an executive assistant agent into leaking a report. | Enforce mutual authentication (mTLS) and cryptographically sign communications between agents. |
| **AGE05** | **Excessive Autonomy** | Permitting an agent to execute multi-step operational chains without verification checkpoints. | An agent gets stuck in an infinite error loop and autonomously opens 10,000 corporate IT support tickets in 5 minutes. | Define hard operational boundaries, maximum loop counters, and timeout thresholds. |
| **AGE06** | **Lack of Human-in-the-Loop** | Designing an agentic pipeline that executes irreversible, high-risk financial or operational tasks with no human oversight. | An autonomous purchasing agent detects a fake low price and spends $200,000 on faulty inventory without approval. | Hardcode manual approval gates into the system architecture for any action involving money or privacy changes. |
| **AGE07** | **Insecure State Management** | Failing to protect the memory tracking files where an agent saves its history, variables, and steps. | An attacker alters an agent's saved session history file, making the agent believe a malicious user is an admin. | Encrypt session states; restrict access permissions to state databases with rigid validation. |
| **AGE08** | **Identity and Access Failures** | Giving an agent a single master corporate login instead of its own restricted, traceable access credentials. | An automated agent gets compromised, and because it uses a human admin's account, hackers gain complete system access. | Issue unique Machine-to-Machine (M2M) API keys to every agent with strict scope limitations. |
| **AGE09** | **Inadequate Logging & Audit** | Failing to record the step-by-step reasoning, tool choices, and inputs executed during an agent's autonomous run. | An agent executes a faulty command that corrupts customer data, but investigators cannot trace *why* or *when* it happened. | Implement continuous trace logging (OpenTelemetry) capturing every single step of the agent's internal logic loop. |
| **AGE10** | **Agentic Denial of Service** | Exploiting an agent's recursive nature to lock it in resource-heavy loops that block system availability. | A user inputs a complex logic puzzle that causes an agent to run continuous compute cycles, freezing server access for customers. | Configure strict resource limits (CPU/Memory caps) and automated loop timeout kills. |

## 🔀 Connecting to General Enterprise Security

AI models and autonomous agents do not run in isolation. They connect to web frontends, rely heavily on cloud computing, and move data back and forth through APIs. 

To secure the traditional software infrastructure that wraps around your AI models, you must also implement traditional security standards.

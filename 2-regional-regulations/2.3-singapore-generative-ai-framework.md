# 2.3 - Singapore Model AI Governance Framework (GenAI Edition)

This handbook serves as a definitive enterprise operational reference for navigating artificial intelligence compliance within Singapore. It maps the **IMDA Model AI Governance Framework for Generative AI** to actionable engineering and corporate process controls.

---

## 🏛️ Module 1: The Singapore AI Governance Architecture

### 1. The Statutory Framework & Oversight
Singapore approaches AI governance through a highly pragmatic, innovation-friendly, risk-management lens led jointly by the **Infocomm Media Development Authority (IMDA)** and the **Personal Data Protection Commission (PDPC)**. 

The framework is anchored by the **Personal Data Protection Act (PDPA) 2012**, alongside the landmark **Model AI Governance Framework for Generative AI (Updated May 2024)**, which directly addresses the structural infrastructure risks introduced by Large Language Models (LLMs) and autonomous agent architectures.

### 2. The Cost of Non-Compliance & Technical Auditing
* **PDPA Financial Fines:** Under Singapore law, data protection violations carry severe statutory penalties—up to **10% of an organization's annual turnover in Singapore** or **SGD 1 million** (whichever is higher).
* **AI Verify Standards:** Singapore does not rely on subjective checklists. The IMDA enforces the use of **AI Verify**, an open-source governance testing framework and software toolkit. It allows enterprises to conduct quantitative, verifiable testing on model fairness, explainability, and technical stability before deployment.

## 📅 Module 2: Evolution & Technical Milestones

* **January 2019:** Singapore releases the 1st Edition of the Model AI Governance Framework at Davos, focusing on traditional machine learning workflows.
* **May 2024:** The IMDA and AI Verify Foundation officially launch the finalized Model AI Governance Framework for Generative AI, establishing the global benchmark for mapping the GenAI supply chain.
* **Continuous Integration:** Any corporate system pulling data from local Singapore cloud environments must execute automated testing runs using the AI Verify toolkit prior to major software release deployments.

## 🔍 Module 4: The 3 High-Risk Operational Strands

To pass a regulatory review under the IMDA guidelines, an enterprise deployment must actively implement three core operational controls:

### 1. Content Provenance & Synthetic Data Labeling
* **The Mandate:** Implement mechanisms to distinguish between human-generated and machine-generated content, minimizing the spread of misinformation or consumer deception.
* **The Operational Fix:** Integrate automated metadata tagging across all AI outputs and ensure all synthetic file assets carry verified cryptographic signatures.

### 2. AI Verify Testing Framework Integration
* **The Mandate:** Utilize standardized, open-source testing methodologies to validate model performance regarding bias, fairness, and safety.
* **The Operational Fix:** Mandate that before steering committee approval, the AI Governance Lead must execute an independent bias evaluation suite against protected demographic datasets using the **AI Verify** codebase.

### 3. Shared Responsibility Mapping (GenAI Supply Chain)
* **The Mandate:** Delineate clear responsibilities between model developers (foundation model builders) and model deployers (enterprises customizing the model via RAG).
* **The Operational Fix:** Execute an internal **Risk Split Assessment Matrix** with the procurement legal team before deploying any vendor API hook, ensuring your data inputs are never utilized for external foundation model training.
